# Finding: QwenPaw Tool Guard

**Date:** June 2026  
**System:** QwenPaw Agent Framework  
**Focus:** `execute_shell_command` tool guard — block rates, bypasses, encoded evasion  
**Method:** 50 direct commands + 30 encoded variants across default and hardened configs

---

## Core Result

| Config | Block Rate | False Positives |
|--------|-----------|-----------------|
| Default | **34.5%** | 3.8% |
| Hardened (ShellEvasionGuardian ON) | **39.3%** | 3.8% |

## Key Findings

1. **Low baseline block rate.** Even with ShellEvasionGuardian enabled, ~60% of dangerous commands pass through. Rule-based regex matching misses novel command structures, shorthand, and context-dependent danger.

2. **Encoded variants largely bypass.** Base64, hex, unicode escape, variable substitution, and backtick obfuscation all evade default detection. Hardened mode catches some but not all — evasion success remains the dominant failure mode.

3. **Minimal false positive tradeoff.** Benign commands (`ls`, `git status`, `df`) are rarely blocked (~3.8%), indicating the guard is conservative rather than overzealous. The problem is under-blocking, not over-blocking.

4. **MITRE ATT&CK mapping validates coverage.** The 84-command test suite maps to 19 techniques across 9 ATT&CK tactics. Coverage is strongest in Execution, Command and Control, and Defense Evasion — weakest in Initial Access and Lateral Movement. See `MITRE_ATTACK_MAPPING.md` in the evaluation code.

## Implication

A rule-based shell command guard is insufficient for agentic systems. The gap between dangerous and benign command syntax is too narrow for regex — semantic understanding of command intent is required.
